### 项目1 分钟讲解

我的项目叫 Uni_Tour， 是一个面向高校参观和择校信息查询场景的校园导览系统，围绕高校基础信息、校区差异、校园 POI 和用户经验分享，帮助用户更直观地了解校园环境和生活信息。

技术上使用了Springboot，Mybatis，MySQL，Redis，JWT，文件上传使用阿里云 OSS，并部署到了自己的云服务器上。整体采用 Controller、Service、Mapper三层架构，以及统一 Result 结果返回还有全局异常处理。

目前主要实现了用户注册登录，JWT 鉴权，高校列表查询，高校详情查询，校区 POI 展示，评价模块，评价模块有评价发布、回复、点赞功能，OSS 图片上传功能，然后使用了 Redis 缓存了高校详情和注册时需要的验证码。

通过这个项目，我重点熟悉了后端接口开发、数据库表设计、MyBatis xml、以及 Redis 的基本使用和项目部署的流程。

### 为什么要做这个项目？

我观察到很多学生择校时主要看分数线、排名和专业，但对校区位置、宿舍、食堂、校园环境、生活便利性这些实际体验了解不够。UniTour 想解决的是从单纯看学校信息，到更全面了解校园生活体验的问题。所以项目除了高校基础信息，还设计了校区、校园 POI、多维评分和用户评价模块。



### 项目整体架构？

项目整体是一个单体的 springboot 后端项目，采用经典的 Controller、Service、Mapper 分层架构。

Controller 层负责接收前端请求，处理参数并返回统一结果；Service 层负责核心业务逻辑哦，比如注册登录，信息查询，评价发布，缓存处理；Mapper 层主要采用 Mybatis XML 映射文件执行 SQL，来操作数据库。

MySQL 负责存储用户、高校、POI、评价、点赞、回复等核心数据。Redis 主要用于注册验证码和高校详情缓存。JWT 用于登录后的身份验证。阿里云 OSS 用于图片上传，数据库中只保存图片的 URL。



### 登录和 JWT 鉴权怎么实现？

用户登录时，前端提交用户名和密码，后端先根据用户名查询用户信息，然后使用 Bcrypt 对密码进行校验。校验通过后，后端会生成一个 JWT 返回给前端。

前端后续访问需要登录的接口时，会在请求头的 Authorization 字段携带这个token。后端通过登录拦截器统一拦截请求，解析 JWT，校验 token 是否有效。如果解析成功，就从 token 中取出用户 ID，并放到 request 中，后续Controller 或者 Service 层就可以知道当前登录用户是谁。

这样做的好处是不用在每个接口里重复写登录校验逻辑，而是把认证逻辑统一放在拦截器中处理。
