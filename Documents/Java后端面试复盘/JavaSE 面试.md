## 面向对象

### 面向对象三大特性是什么？

三大特性是封装、继承、多态。

封装是指将对象的属性和行为封装在类中，通过 public、private 等修饰符控制外部访问，不允许外部直接访问对象内部的信息，但是可以提供一些可以被外部访问的方法来操作属性，隐藏了实现细节，提高安全性和可维护性。

继承是指将子类共有的属性和行为抽取到父类中，子类继承父类中可以被访问的成员，可以复用和重写父类的方法，还可以扩展自己的方法，提高了代码的复用性。

多态即一个对象拥有多种形态，具体表现为父类引用指向子类实例，子类重写父类或接口方法，父类引用和子类实例之间具有继承或接口实现的关系，在调用方法时根据运行时对象的具体形态来执行不同实现，可以提高代码扩展性，降低耦合。



### 怎样理解多态？

多态是 Java 面向对象的一个重要特性，一种对象拥有不同的状态，表现为父类引用指向子类实例。

多态通常要求：具有继承或接口实现的关系、子类重写父类的方法，父类引用指向子类实例。

好处是可以提高代码的扩展性，降低耦合、让程序面向接口或父类编程。



### int 和 Integer 有什么区别？

int 是基本类型，Integer 是 int 的包装类，属于引用类型。作为成员变量时，int 默认值是 0，Integer 默认值是 null。

Integer 可以用于集合和泛型，也可以调用方法，而 int 不行。

二者之间有自动装箱和自动拆箱，自动装箱是把 int 转成 Integer，自动拆箱是把 Integer 转成 int。如果 Integer 为 null 时发生自动拆箱，会抛出 NullPointerException。

比较时，int 可以用 == 比较数值；Integer 如果两个对象之间用 == 比较，比较的是引用地址，所以一般应该用 equals 或 Objects.equals 比较值。

Integer 还有缓存机制，自动装箱或 Integer.valueOf 时，默认会缓存 -128 到 127 范围内的对象，所以这个范围内的两个 Integer 用 == 比较可能为 true，超过这个范围通常为 false，但开发中不应该依赖 == 比较 Integer 的数值。



### 什么是 Integer 缓存池？

`Integer` 缓存池是 `Integer` 类内部的一种缓存机制。默认会缓存 `-128` 到 `127` 范围内的 `Integer` 对象。
 当发生自动装箱时，比如 `Integer a = 127`，底层会调用 `Integer.valueOf(127)`。如果数值在缓存范围内，就会直接返回缓存中的对象，而不是创建新对象。
 所以 `Integer a = 127; Integer b = 127; a == b` 通常是 `true`，因为它们引用的是同一个缓存对象。
 但如果是 `Integer a = 128; Integer b = 128;`，超出了默认缓存范围，通常会创建不同对象，所以用 `==` 比较是 `false`。
 因此包装类比较数值时不建议用 `==`，应该使用 `equals()` 或 `Objects.equals()`。



### 深拷贝和浅拷贝的区别是什么？

浅拷贝：浅拷贝会在堆上创建一个新对象，然后把原对象的字段值复制一份。
如果字段是基本类型，复制的是具体值；如果字段是引用类型，复制的是引用地址，所以新旧对象会指向同一个内部对象，即复制基本类型，共用引用类型。

深拷贝：深拷贝也会在堆上创建一个新对象，但它会将原对象内部引用的其他对象也复制一份，不再和原对象共享一个引用对象，修改其中一个对象中的引用字段，一般不会影响另一个对象



### 什么是方法重载和方法重写？

方法重载是指在同一个类中，方法名相同但是参数列表不同，参数列表不同是指参数个数不同，参数类型不同和参数顺序不同，与返回值类型无关，返回值类型不同不构成方法的重载

而方法的重写是发生在父类和子类之间的，子类重新实现父类中的方法，重写要求方法名一样，参数列表相同，返回值类型相同或者是父类返回值的子类，而且子类方法的访问权限不能比父类更加严格，父类中被 final 和 private 修饰的方法不能被重写。

方法重载是编译时多态，而方法重写是运行时多态。



### 抽象类和接口的区别？

抽象类和接口都可以实现抽象。

抽象类更偏向描述一类对象的共同属性和行为，子类通过 extends 继承，但 Java 只能单继承，不支持多继承。抽象类中可以有成员变量、普通方法、抽象方法和构造方法，不能直接创建对象。

接口更偏向定义行为规范，类通过 implements 实现，一个类可以实现多个接口，一个接口也可以继承多个接口。接口中的变量默认是 public static final，方法默认是 public abstract，Java 8 后也可以有默认方法和静态方法。

简单来说，有共同属性和父子关系时用抽象类；定义能力规范、降低耦合时用接口。



### public、protected、default、private 的区别？

这四个都是访问修饰符，其中 public 的访问权限最大，任何地方都能访问，接下来是 protected，可以在本类、同包、不同包子类中访问，但是不能在不同包的非子类中访问。接下来是 default，也叫默认访问权限，也就是不写修饰符，可以在本类、同包中访问，不同包不能访问。private 的访问权限最小，只能在本类中访问。



### `equals（）`和`==`的区别是什么？

`==`对于基本类型比较值，对于引用类型比较地址值

而 `equals（）`不能用来比较基本类型，只能用来比较对象，默认比较地址值，但很多类比如 `String` 、`Integer` 类都会重写 `equals（）`方法，用来比较对象的内容

所以基本类型比较值的话选择`==`，如果要比较对象的内容，则重写`equals()`方法使用`equals()`进行比较



### Object 类有哪些常见方法？

Object 是 Java 中所有类的父类，所以所有对象默认都拥有 Object 中的方法。常见方法有 equals()、hashCode()、toString()、getClass()、clone()、wait()、notify()、notifyAll() 等。

equals() 默认比较对象地址，很多类会重写它来比较对象内容；hashCode() 返回对象的哈希值，常和 equals() 配合用于 HashMap、HashSet 这类哈希容器；toString() 返回对象的字符串表示，通常会重写方便调试；getClass() 用来获取对象运行时的 Class 对象，反射中经常用到；clone() 用来复制对象，默认是浅拷贝；wait()、notify()、notifyAll() 用于线程间通信。



### 为什么重写 `equals（）`方法的时候一定要重写 `hashCode（）`？

在 `HashMap`、`HashSet` 这类哈希容器中，`hashCode()` 和 `equals()` 通常是配合使用的。哈希容器会先根据对象的 `hashCode()` 定位存储位置，然后再通过 `equals()` 判断两个对象是否真正相等。
 如果两个对象 `equals()` 返回 `true`，但它们的 `hashCode()` 不同，那么它们可能会被定位到不同的位置，后续 `equals()` 比较可能根本没有机会执行，导致 `HashSet` 去重失败，或者 `HashMap` 查找失败。
 所以 Java 约定：如果两个对象 `equals()` 相等，那么它们的 `hashCode()` 必须相等。因此重写 `equals()` 时通常也必须重写 `hashCode()`。

## 关键字

### `final` 关键字的作用是什么

final 关键字可以用来修饰类、方法和变量。

如果修饰类，则表明这个类不能被继承，是最终形态（最终类）

如果修饰方法，则该方法不能被重写

如果修饰变量，则表明该变量一旦被赋值就不能再改变，如果修饰的是引用类型，该引用变量记录的地址值不能发生变化，即该引用变量不能指向其他对象，但是对象本身的内容是可以变化的比如

```java
StringBuilder sb = new StringBuilder();
```

该引用变量不能再指向其他 `StringBuilder` 对象，但是可以进行 `sb.append(“hello world”);`来修改字符串的内容。

### `static` 关键字有什么作用？

`static` 表示静态，被`static`修饰的成员属于类本身，而不是属于单个对象。

`static`可以修饰方法、成员变量、代码块、内部类。修饰成员变量时叫做静态变量，所有对象共用一个同一份数据，可以通过类名直接访问。修饰方法时教静态方法，也可以通过类名直接调用，常用于工具类。

`static`还可以用来修饰代码块，静态代码块会在类加载的时候执行，并且只执行一次，常用语初始化资源，实际开发中常用`static final`来定义常量。

## String

### String 为什么不可变？

首先，String 这个类是用 final 关键字修饰的，所以 String 这个类不能被继承，从而避免了子类重写 String 中的方法来破坏其不可变性。

其次，String 中保存字符串内容的数组是被 private final 修饰的，private 保证了不能被外界直接访问，final 保证了这个引用类型不能指向其他地址，但final 不能保证字符串内容是不变的，所以还要靠 private 进行封装和不提供修改方法。在 Java8 及以前采用 char 类型的数组来存储字符串内容，Java9 之后进行了优化，开始采用 byte 类型的数组来存储。

另外，String 中并没有对外界提供修改字符串内容的方法，像 concat，replace 这些看似修改字符串的方法都会返回一个新的 String 对象，从而保证了字符串内容的不可变性。

所以 String 是不可变的，这样可以使得我们可以安全地使用字符串常量池，里面的字符串不会变化，文件路径、网络地址等关键信息也都用 String 进行存储，所以 String 的不可变性也提高了安全性，而且 String 不可变保证了 hashCode 的稳定性，适合作为 HashMap 中的key，并且不可变对象天然线程安全，保证了多线程的安全性。



### String、StringBuilder、StringBuffer 区别？

String 是**不可变字符串**，每次拼接都会产生新的字符串，适合少量字符串操作或者内容不频繁变动的场景。

StringBuilder 是**可变型字符串**，可以在原对象内部追加或者修改内容，**适合单线程下大量字符串拼接，性能较好，但线程不安全**。

StringBuffer 也是**可变型字符串**，功能与 StringBuilder类似，但是在它的方法中大多使用了**sychronized** 修饰，是**线程安全**的，但**性能相较 StringBuilder 较低**。

所以少量字符串操作选择 String，单线程大量拼接使用 StringBuilder，多线程共享同一个字符串缓冲区可以使用 StringBuffer



### String s = "abc" 和 new String("abc") 区别？

String s = "abc" 使用的是字符串字面量方式创建字符串。它会先去字符串常量池中查找是否已经存在 "abc"，如果存在，就直接让 s 指向常量池中的对象；如果不存在，就在常量池中创建 "abc"，然后让 s 指向它。

String s = new String("abc") 会使用 new 关键字在堆内存中创建一个新的 String 对象，s 指向的是堆中的对象。同时，"abc" 这个字面量本身也会进入字符串常量池。如果常量池中之前没有 "abc"，则还会在常量池中创建一个 "abc"；如果已经有了，就直接复用常量池中的 "abc"。

所以两者的区别是：前者指向字符串常量池中的对象，后者指向堆中新创建的 String 对象。用 == 比较通常是 false，用 equals 比较是 true。



### 字符串常量池是什么？

字符串常量池是 JVM 为了**复用字符串**对象而维护的一片区域，主要用来保存字符串字面量。

在使用 String s = “abc” ;这种方式创建字符串时，JVM 会先去字符串常量池中寻找“abc”对象，如果存在，则将引用直接指向该对象，如果不存在，则会现在字符串常量池中创建该字符串对象。

字符串常量池的作用是**复用相同内容的字符串**，**减少重复对象的创建，节省内存。**

String 中的intern（）方法也和字符串常量池有关，它会返回字符串在常量池中的引用。



### String 拼接时底层发生了什么？

如果是字面量拼接，那么在编译期间就会直接进行优化，不会在运行期间真正执行多次拼接

如果有变量参与拼接，那么会在运行期间进行拼接，在 Java8 及以前都是使用 StringBuilder 的 append（）方法进行拼接，然后通过 toString（）方法产生新的字符串对象，在 Java8 以后主要通过 invokedynamic 和 StringConcatFactory 进行优化。

要尽量避免在循环中使用 String +=这种形式来循环拼接，会产生大量的中间对象，效率低且占用内存。推荐使用 StringBuilder 的 append（）方法进行拼接

## 集合

### ArrayList 和 LinkedList 区别？

ArrayList 底层是**动态数组**，支持根据下标随机访问，所以查询效率高，get 操作复杂度是 O(1)。但是如果在中间插入或者删除元素，后面的元素需要整体移动，所以中间插入删除效率相对较低。

LinkedList 底层是**双向链表**，不支持像数组一样通过下标直接定位元素。按下标访问时需要从头或尾开始遍历，所以随机访问性能较差。但是如果已经定位到要插入或删除的节点，只需要修改前后节点的引用，不需要移动大量元素，因此插入删除效率较高。

不过实际开发中 ArrayList 更常用，因为大部分场景是查询、遍历和尾部追加，ArrayList 内存占用也更低；LinkedList 每个节点还要额外保存前驱和后继引用，内存占用相对更高。



### ArrayList 扩容机制？

ArrayList 使用无参构造方法创建时，内部一开始是一个空数组，并不会立即创建长度为 10 的数组。

当**第一次执行 add 操作**时，会**默认扩容到容量 10**。之后如果容量不够，通常会扩容为**原容量的 1.5 倍**。如果 1.5 倍仍然不够容纳新增元素，则会使用实际需要的容量。

扩容过程不是在原数组上直接变长，因为数组长度固定。ArrayList 会创建一个更大的新数组，然后把旧数组中的元素复制到新数组中，再让内部引用指向新数组。

所以扩容是有一定成本的。如果提前知道大概需要存储多少元素，可以在**创建 ArrayList 时指定初始容量，减少扩容次数**。



### ArrayList 为什么查询快、增删慢？

因为 ArrayList 的底层是**动态数组**，**支持数组下标直接进行访问**，get（）操作的时间复杂度是 O（1），所以查询快，但是如果要在中途添加或删除元素，则需要统一移动后面的元素，性能较差，所以中间插入和删除的效率相对较低，时间复杂度通常是 O（n）



### LinkedList 为什么增删理论快，但实际不一定常用？

因为我们实际生活中**大多数场景都是在查询，遍历和尾部添加**，使用 ArrayList 即可达到预期效果，内存连续，不仅随机访问的效果好，而且节省内存。LinkedList 增删快也只是针对于**已经定位到目标节点**的清况下，如果没有定位到目标位置，还需要从头部和尾部开始定位，而且 LinkedList 需要维护前驱指针和后继指针，内存占用较大，随机访问的效果也差，所以实际不一定常用。



### HashMap 底层数据结构是什么？

HashMap 底层是**数组 + 链表 + 红黑树**。
数组用于快速定位桶 bucket。
链表用于解决哈希冲突。
红黑树用于优化长链表查询性能。
树化条件：链表长度 >= 8 且数组容量 >= 64。



### HashMap put 流程大概是什么？

HashMap 在 put 时，首先会根据 key 计算 hash 值。在 JDK 8 中，会先调用 key 的 hashCode 方法，然后将 hashCode 的高 16 位和低 16 位进行异或扰动，尽量让高位也参与下标计算，从而减少哈希冲突。

接着通过 (数组长度 - 1) & hash 计算数组下标。如果该下标对应的桶为空，就新建一个 Node 节点放到该位置。Node 中保存 hash、key、value 和 next。

如果桶不为空，就需要判断 key 是否已经存在。如果 key 已经存在，则用新 value 覆盖旧 value。如果 key 不存在，则根据当前桶的数据结构判断插入方式。如果是链表结构，就遍历链表并将新节点插入到链表尾部；如果是红黑树，就按照红黑树的方式进行插入。

插入后还要判断链表是否需要树化，以及 size 是否超过扩容阈值。如果 size 超过阈值，就会触发扩容。

### HashMap 为什么需要 hashCode 和 equals？

HashMap 是根据 key 值来存取 value 的

**hashCode（）用于计算对应的 hash 值，来定位在数组中桶的位置，可以提高查找效率。**

但是不同的key 值有可能计算出相同的桶的位置，也就是发生哈希冲突，所以还需要 **equals（）方法比较两个 key 值是否真正相等**。

在put 时，如果 hash 相同且 equals（）返回  true，则会用新 value 覆盖旧 value，如果 hash 相同但是 equals（）返回 false，则说明只是哈希冲突，不是同一个key，则需要放到链表或者红黑树当中。

### HashMap 什么时候扩容？

HashMap 通常会在 put 新元素后判断是否需要扩容。

**如果本次 put 是新增 key，size 会加一**。当 size **超过**扩容阈值 threshold 时，就会触发扩容。

扩容阈值 threshold = capacity * loadFactor。默认初始容量是 16，默认负载因子是 0.75，所以默认阈值是 12。

扩容时 HashMap 的容量通常会变为原来的 **2 倍**，并**重新分布原来的元素**。

**如果 put 的 key 已经存在，只是覆盖旧 value**，不会增加 size，一般不会因为这次操作触发扩容。HashMap 默认初始容量和负载因子是多少？



### HashMap 为什么容量是 2 的幂？

**主要是为了使用（n - 1）& hash 来计算数组下标。**

当容量是 2 的幂时，**（数组长度 - 1 ）的二进制才会是低位全是 1 的形式**，从而（ 数组长度 - 1 ）& hash才能达到对数组长度去余的效果，而且**按位与运算的效率比模运算的效率高**，从而算出的下标范围在 0 到 n-1 之间。如果不是 2 的幂，那么n - 1 的二进制低位就不是全 1，**可能导致下标分布不均匀，增加哈希冲突** 。

因此容量必须是 2 的幂。



### JDK 1.8 后为什么引入红黑树？

在 JDK1.8 以前，HashMap 底层主要是采用数组+链表，如果大量的 key 落到同一个桶中，会导致链表长度很长，查询某一个 key 值时需要从头遍历，时间复杂度可能退化到O（n）

在 JDK1.8 以后，HashMap 引入了红黑树，红黑树是一种近似平衡的二叉搜索树，可以将查询的复杂度降低到O（logn），提升哈希冲突时查询性能

但是红黑树的维护成本比链表高，节点较少时使用链表反而简单，只有当链表长度达到 8 且数组长度至少 64 时才会将链表树化，如果数组容量还比较小，则优先扩容。



### HashMap 和 Hashtable 区别？

1.线程安全不同，HashMap 线程不安全，Hashtable 线程安全。

2.对 null 的支持不同，HashMap允许一个 null key 和多个 null value，但是 Hashtable 不支持，会出现空指针异常

3.继承结构不同，HashMap继承自 AbstractMap，Hashtable 继承自 Dictionary

4.使用场景不同，在实际开发中如果是单线程或者外部保证线程安全，则优先使用 HashMap，如果需要并发安全的场景，则选择 ConcurrentHashMap，而不是 Hashtable



### HashMap 和 ConcurrentHashMap 区别？可以先了解

HashMap：线程不安全，允许 null。
ConcurrentHashMap：线程安全，不允许 null。
JDK 7：Segment 分段锁。
JDK 8：数组 + 链表 + 红黑树，CAS + synchronized。
ConcurrentHashMap 锁粒度更细为桶级别，性能比 Hashtable 好。



### HashSet 底层是什么？

HashSet 的底层是 HashMap，在 HashSet 底层维护了一个 HashMap，当我们往 HashSet 中添加元素时，会将元素当做 HashMap 的 key 存储，而 value 是一个固定的 Object 占位对象。

因为 HashMap 中的 key 不能重复，所以 HashSet 不能存储重复元素。在 HashSet 中主要依赖元素的 hashCode（）方法和 equals（）方法判断元素是否重复，首先根据 hashCode（）定位元素的存储位置，然后再根据 equals（）方法精确判断元素是否相等。

如果我们在 HashSet中存放自定义对象，并且希望根据元素的内容进行去重的时候，需要同时重写 equals（）和 hashCode（）方法。



### Collection 和 Map 的区别？

Colletion 和 Map 是 Java 集合体系的两个顶层接口。

Collection 是单列集合，一般用来存放一个个独立的元素，其实现类主要有 List，Set，Queue。List 的特点是有序可重复，Set 的特点是无序不可重复，而 Queue 一般用来表示队列结构。

Map 是双列集合，用来保存 key-value 键值对，一个 key 对应一个 value，且 key 不可重复，常见实现类有 HashMap，TreeMap，ConcurrentHashMap 。

Collection 适合保存一组对象，而 HashMap 适合根据 key 快速查找对应的 value。

## 异常机制

### Exception 和 Error 区别？

在 Java 中所有异常和错误的顶层父类是 Throwable 类，Throwable 类下面主要有两个子类 Error 和 Exception。

Error 主要表示系统级严重错误，比如 OutOfMemoryError，StackOverflowError，这类问题主要是 JVM 和资源层面的问题，程序一般无法处理，也不建议使用 try-catch 捕获

Exception 主要表示程序运行中可以预料可以处理的异常，比如 IOException，SQLException，NullPointerException 等，通常可以使用 try-catch、throws、全局异常处理机制进行处理。

所以 Error 主要偏向于系统级严重错误，而 Exception 主要偏向程序级异常，是我们日常开发中重点关注和处理的对象。

### Checked Exception 和 Unchecked Exception 区别？

Checked Exception 和 Unchecked Exception 的主要区别是编译器是否强制处理

Checked Exception 也叫受检异常，主要是 Exception 中除了 RuntimeException 及其子类之外的异常，比如 IOException、SQLException、ClassNotFoundException 等。编译器要求我们要强制处理，要么使用 try-catch 捕获异常，要么使用 throws 向上抛出。

Unchecked Exception 也叫非受检异常，主要是 RuntimeException 及其子类，广义上也包括 Error，比如 NullPointerException，ArrayIndexOutOfBoundsException 等，编译器不要求我们强制处理，这些问题往往都是代码逻辑的问题，可以通过参数校验、边界判断、代码修复等措施避免。

受检异常更偏向于外部资源、外部环境、类加载等不可完全由程序控制的问题，编译器需要强制处理，而非受检异常更偏向代码层面的问题，通常不建议到处捕获，而应该从代码层面避免。

（运行时异常并不是只有在运行时才会发生，所有异常本质上都是在运行时发生的，运行时异常是指 RuntimeException 这一类，编译器不需要显式处理）

### throw 和 throws 区别？

throw 和 throws 都和异常处理有关，但是使用位置和作用不同。

throw 使用在方法内部，后面跟的是一个具体的异常对象，表示主动抛出一个异常。比如 throw new RuntimeException（”参数错误“）。一旦执行，则当前方法后面的代码就不会再执行，异常会向上抛给调用者。

throws 使用在方法声明上，后面跟的是一种或多种异常类型，表示这个方法可能会抛出这些异常，不一定真的会抛出，当前方法不处理，交给调用者处理，调用者可以使用 try-catch 捕获，也可以继续向上抛出。

throw 是真正抛出异常，而 throws 只是声明可能会抛出异常。对于受检异常一旦使用 throw 进行抛出但没有进行捕获，那么方法签名上必须使用 throws 进行声明，但是对于 RuntimeException ，编译器不要求强制处理。

### try-catch-finally 执行顺序？

顺序是先执行 try，如果 try 中没有发生异常，则会跳过 catch，直接执行 finally

如果 try 中发生了异常，会跳过发生异常之后的代码寻找匹配的 catch，如果匹配到了对应的catch，则会执行 catch，最后执行 finally，但如果没有匹配到对应的catch，则会跳过 catch 直接执行 finally，然后异常继续向上抛出。

如果 try 和 catch 中有 return ，则finally 中的代码会在return 前执行，如果 finally 中也有 return 的话，finally 中的 return 会覆盖 try 和 catch 中的 return，所以我们一般不建议在 finally 中 写return。

### finally 一定会执行吗？

finally 通常会执行，但不是绝对一定执行。

通常无论 try 中是否发生异常，catch 是否捕获到异常，甚至 try 和 catch 中有 return，finally 都会在方法真正结束前执行。

但是如果JVM 被直接终止，比如System.exit(0)，或者 JVM 崩溃、系统断电、线程被直接终止还有try 或者 catch 中出现死循环，那么 finally 就没有机会执行。

所以只要程序能正常走出 try-catch 模块，finally 就会执行，但如果 JVM 或者线程执行环境被直接终止，则 finally 就不会执行。

### return 和 finally 同时出现怎么执行？

如果return 出现在 try 和 catch 中，那么程序会先计算并暂存这个返回值，然后执行 finally，最后再真正返回。

如果 finally 中没有return，一般不会改变已经暂存好的基本类型返回值；但如果返回类型是引用类型并且 finally 中修改了对象内部状态，那么最终返回的对象内容可能会受到影响。

如果 finally 中有return，那么 finally 中的return 会覆盖掉 try 和 catch 中的return 返回值，如果 finally 中抛出了异常，也会覆盖原本准备返回的结果。

所以在实际开发中，不建议在 finally 中使用 return 或者抛出新的异常，这样会造成代码混乱，甚至吞掉原来的异常或者返回值。



### 项目中一般怎么处理异常？

项目中一般不会在每个 Controller 或 Service 中到处写 try-catch，而是采用统一异常处理机制。

在业务代码中，如果遇到用户不存在、密码错误、无权限操作、资源不存在等可预期问题，可以主动抛出业务异常，然后通过 @RestControllerAdvice 和 @ExceptionHandler 定义全局异常处理器，统一捕获异常，并返回统一格式的响应结果，比如 Result。

对于业务异常，可以把明确的错误信息返回给前端；对于系统异常，比如空指针、数据库异常、Redis 异常等，一般会在后端记录日志，前端只返回通用错误提示，避免暴露堆栈信息。

只有在当前方法能真正处理异常时才使用 try-catch，比如调用文件上传、第三方服务或 IO 操作失败时，可以捕获底层异常，记录日志后转换成业务异常抛出。

我当前项目中也是通过统一返回结果和全局异常处理来处理异常，不过目前主要是抛运行时异常，后续可以进一步抽象成自定义业务异常和错误码，让异常处理更规范。

## 泛型

### 泛型是什么？

泛型是 Java 中提供的一种类型参数化机制，在定义类、接口、方法的时候可以先用类型参数占位，不写死，在使用的时候再指定具体类型。主要解决类型安全和代码复用的问题。比如使用 List<String>那么就表明该集合中只能存放 String 类型，不能放其他类型。在项目中使用Result<T>可以让统一返回结果适配不同的返回类型。需要注意在 Java 中泛型主要在编译期间起作用，在运行期间会发生泛型擦除。



### 泛型有什么好处？

一是提高类型安全，比如 List<String>规定集合中只能存放String 类型，如果存放其他类型，编译期间就会报错，可以把一部分运行时类型错误提前到编译期发现。

二是减少强制类型转换，没有泛型时，从集合中取数据要进行强转，有了泛型之后，编译期间就知道元素类型，取元素的时候不用进行强转。

三是提高代码的复用性，比如项目中的 Result<T>可以使得统一返回结果适配不同类型的数据。不用为每个类型的返回结果单独定义一个类。



### 泛型擦除是什么？

泛型擦除是指泛型主要在编译期间起作用，编译器会利用泛型进行类型检查，但是在运行期间泛型的类型信息会被擦除。

比如 List<String>，List<Integer>在运行期间泛型的类型信息都会被擦除，它们的类型都是 ArrayList，不会保留 String 和 Integer 的信息。

如果泛型没有指定上界，类型参数通常会被擦除成 object 类型；如果指定了上界，比如`<T extends Number>`那么类型参数会被擦除成上界 Number



### List<?>、List<? extends T>、List<? super T>

List<?> 表示未知类型的 List，可以接收任意类型的 List，但是因为具体元素类型未知，所以一般只能安全地读取为 Object，不能随便添加元素。

List<? extends T> 表示元素类型是 T 或 T 的子类，也叫上界通配符。因为可以确定取出来的元素至少是 T 类型，所以适合读取，可以安全地读成 T；但是不能随便写入，因为编译器不知道它实际到底是 List<T> 还是某个子类的 List。

List<? super T> 表示元素类型是 T 或 T 的父类，也叫下界通配符。因为无论实际是 T、T 的父类还是 Object，都可以安全地放入 T 或 T 的子类，所以适合写入；但读取时只能安全地读成 Object。

简单记就是：extends 适合读，super 适合写。泛型通配符常见原则是 PECS，Producer Extends，Consumer Super。



## 反射

### 反射是什么？

反射是 Java 中提供的一种**在运行期间动态地操作类或对象的机制**，通过反射，程序可以在运行期间获取一个类的 class 对象，然后获取它的构造方法、成员变量、方法、注解等信息，动态地创建对象、访问属性、调用方法。

优点是灵活，能让程序在运行时动态地处理对象；缺点是性能比直接调用差，可能破坏封装性，使代码可读性变差。



### 反射可以做什么？

在运行期间动态地获取类的信息，并且动态地操作这个类的对象。

具体来说，反射可以在运行期间获取类名、构造方法、成员变量、方法、注解等信息，还可以动态地创建对象、访问属性、调用方法

比如在 Spring 框架中，可以通过扫描带有@Service、@Controller 的类，通过反射创建对象并放入 IOC 容器里，也可以通过反射来实现依赖注入和方法调用。



### 反射的缺点？

反射的缺点是比直接调用性能差、可能破坏封装性、代码可读性差。



## 注解

### 注解是什么？

注解是 Java 中提供的一种元数据机制，可以给类、字段、方法、参数等程序元素添加额外信息。注解本身通常不直接改变业务逻辑，而是通过编译器、框架、运行时工具读取后进行相应处理。

比如 @Override 是给编译器看的，用来检查方法是否正确重写；@RestController、@Service、@GetMapping 这类注解是给 Spring 框架看的，Spring 会在启动或运行时读取这些注解，完成对象创建、依赖注入、请求映射等功能。

注解通常和反射搭配使用，注解负责提供标记信息，反射通过在运行时动态获取这些信息并进行处理，比如 Spring 扫描到有@Service 的类后可以通过反射创建对象并放进 IOC 容器。
